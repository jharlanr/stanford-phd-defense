# Elmer/Ice bundle — MGSIM bed ensemble for lake 1951 (2019cw428)

Self-contained. Copy this whole directory to the VM, run one script, get 20
viscous Elmer/Ice solutions: each of the 10 MGSIM beds run **with** and
**without** the slippery patch, so every realization yields a Δσ₁.

```bash
scp -r elmer_bundle/ <vm>:~/            # or gcloud compute scp --tunnel-through-iap
cd elmer_bundle && ./run_ensemble.sh    # MAX_PARALLEL=4 by default
```

## What is in here

```
elmer_bundle/
├── run_ensemble.sh                     # mesh once, then solve all 10
├── 2019cw428_d25km_r2500m.geo          # published mesh geometry (copy)
├── PROG/USF_TAVz{,.F90}                # published temperature UDF (copy)
├── dems/
│   ├── 2019cw428_bed_..._mgsim00..09.dat   # the 10 MGSIM realizations
│   └── 2019cw428_surface_...dat            # published surface (copy)
├── sifs/2019cw428_glen_..._{patch,nopatch}_mgsim00..09.sif  # 20 solver inputs
└── MANIFEST.txt                        # sha256 + sizes, to verify the transfer
```

The mesh is built **once** and shared: the bed enters through `bedDEM`
(`Bottom Surface = Equals bedDEM`), not through the mesh footprint, so all ten
runs use the identical mesh.

## Provenance — what differs from the published run

Generated by `../scripts/make_elmer_bundle.py` from the published sif
`2019cw428_glen_d25km_r2500m_tsic_base.sif` (sanctioned copy in
`../data/source_copies/`, taken read-only from
`sgl-stress/3d/simulations/realtopos/2019cw428/step1glen_patch/`).

`diff` against the published sif is **exactly** these five edits, nothing else:

1. `bedDEM_path` → the realization's DEM.
2. `ZsDEM_path` → written as a literal lowercase filename. The published sif
   assembles `"_bed_D25km_H1004_"` with capitals while the files on disk are
   lowercase — harmless on macOS, **fatal on Linux**. Fixed here.
3. The `Variable 3` (`speedDEM`) block in Solver 1 and its
   `Exported Variable 5` in Solver 3 are removed. Diagnostics only; the
   `*_speed_*.dat` was never archived, and nothing else references it.
4. `out_path` / `vtu_path` gain the realization tag so the 10 runs do not
   collide.
5. The UDF path is rebased `../../PROG` → `PROG` for this layout.
6. `Output File` (the ~466 MB `.result` restart dump) is **not written** —
   σ₁ comes from the `.vtu`, and 20 `.result` files would not fit on the VM.
   Re-add `Output File = File $out_path` under `Simulation` to restore it.

The `nopatch` sifs differ from their `patch` twin by exactly two lines:
`patch_nopatch_str` (which only names the output) and the Weertman friction
coefficient, `"(1 - ((...) < R^2)) * C_out"` → `"C_out"`, i.e. C_out
everywhere instead of zero inside R = 2500 m.

Everything physical is byte-identical to the published run: **Csi = 6.5e6**,
the SICOPOLIS temperature profile (c0..c4), Glen rheology and Cuffey–Paterson
prefactors, the slippery patch (`patch`, R = 2500 m, C = 0 inside), all six
boundary conditions, 10 extruded levels, and every solver setting.

The `patch` set is byte-identical to the published configuration apart from
the six edits above; the `nopatch` set adds the two-line change described
there.

## Outputs

Per realization:

- `2019cw428_d25km_r2500m_Csi6.5e6_Tsic_{patch,nopatch}_mgsim<NN>_cauchy_t0001.vtu`
  (~188 MB each; 20 of them ≈ 3.8 GB)
- `logs/<sif>.log`, and `logs/<sif>.done` on success (re-running skips
  completed realizations, so an interrupted batch resumes cleanly)

The ensemble beat needs `EigenStress` (σ₁) at the top surface from each `.vtu`.

## Notes

- `PROG/USF_TAVz` is the published **Linux x86-64** build, so it drops straight
  onto the VM; it will not load on an arm64 Mac. If the VM's Elmer disagrees
  with it, rebuild from the included source:
  `elmerf90 PROG/USF_TAVz.F90 -o PROG/USF_TAVz`.
- `NATIVE=1 ./run_ensemble.sh` skips docker if gmsh/ElmerGrid/ElmerSolver are
  already on PATH.
- All runs share the mesh directory read-only and write distinct output names.
  If anything looks odd, `MAX_PARALLEL=1 ./run_ensemble.sh`.
- Verify the transfer: `shasum -a 256 <file>` against `MANIFEST.txt`
  (first 16 hex chars).
